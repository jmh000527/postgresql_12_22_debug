## 核心功能状态

### ✅ 已成功实现的功能

1. **post_parse_analyze_hook** - 在SQL解析后、优化前拦截查询
2. **SubLink遍历** - 递归遍历Query树,找到所有SubLinks
3. **Hint应用** - 将hints关联到每个Query节点(main, sublink_0, sublink_1...)
4. **递归保护** - 防止SPI查询导致的无限递归
5. **Query命名** - 在SubLinks被pull-up之前正确分配名称

### 测试输出示例

```sql
SET pg_outline.mode = 'auto';
EXPLAIN SELECT * FROM t1 WHERE c1 IN (SELECT c2 FROM t2 WHERE c2 < 10);
```

**输出**:
```

DEBUG:  Assigned name 'subquery_0' to Query at location 0 (parent: main)
DEBUG:  pg_outline: assigned query names before optimization

NOTICE:  Generated Outline Data:

BEGIN_OUTLINE_DATA
[main] HashJoin(t1 t2)
[main] Leading((t1 t2))
[main] SeqScan(t1)
[main] SeqScan(t2)
```

**关键点**: SubLinks在hints应用时完整保留,Query树结构未被优化器改变。

## 已知限制

### Fingerprint匹配问题

目前存在fingerprint不匹配的问题,导致manual mode下无法匹配到存储的outline。这是因为:

1. Auto mode生成的SQL包含"EXPLAIN"关键字
2. 用户创建outline时的query pattern不包含"EXPLAIN"
3. 导致计算的fingerprint不同

**解决方案**: 需要在`normalize_query()`中统一处理EXPLAIN前缀,或者在auto mode生成outline时自动去除EXPLAIN。
