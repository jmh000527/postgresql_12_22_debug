# 内联提示解析改进方案

## 问题分析

您提到的问题是：内联提示（inline hints）没有被正确解析和分配给对应的Query结构。在您的测试用例中：

```sql
EXPLAIN SELECT /*+ NestLoop(c o) */
  c.name,
  (SELECT /*+ SeqScan(orders) */ MAX(amount) FROM orders WHERE customer_id = c.id) as max_amt
FROM customers c
JOIN orders o ON c.id = o.customer_id
WHERE c.id IN (SELECT /*+ IndexScan(customers) */ id FROM customers WHERE id < 50);
```

结果显示所有Query都没有提示：
```
NOTICE:  Query 'main' has no hints
NOTICE:  Query 'subquery_0' has no hints
```

## 根本原因

原有实现存在以下问题：

1. **固定距离匹配**：使用固定的100字符最大距离，对于格式复杂的SQL不够灵活
2. **首次匹配策略**：返回第一个找到的提示，而不是最接近的提示
3. **缺少消费追踪**：提示可能被多次匹配给不同的Query
4. **调试信息不足**：难以诊断为什么提示没有被匹配

## 解决方案

我参考了**pg_hint_plan**的实现方式，对提示解析逻辑进行了全面增强：

### 1. 最近匹配算法

实现了一个**最近距离匹配算法**：

- 搜索Query的`stmt_location`之前**最近的未消费提示**
- 提示到Query的最大距离从100字符增加到**200字符**（更宽松）
- 每个提示只能匹配一次，匹配后标记为"已消费"

```c
// 核心逻辑：
// 1. 遍历所有提示位置
// 2. 跳过已消费的提示
// 3. 查找在Query位置之前且距离最近的提示
// 4. 匹配成功后标记为已消费
```

### 2. 消费追踪机制

在`QueryHintPosition`结构中添加了`consumed`标志：

```c
typedef struct QueryHintPosition
{
    int     hint_location;  // 提示开始位置
    int     hint_end;       // 提示结束位置
    char   *hint_text;      // 提示文本
    bool    consumed;       // 是否已被匹配 (新增)
} QueryHintPosition;
```

这确保了每个提示只会被分配给一个Query，避免重复匹配。

### 3. 详细调试日志

添加了全面的调试日志，帮助您了解匹配过程：

```
DEBUG: Processing Query at stmt_location=15, commandType=1
DEBUG:   Hint at location 15-35: 'NestLoop(c o)'
DEBUG:   Hint at location 52-75: 'SeqScan(orders)'
DEBUG:   Hint at location 156-184: 'IndexScan(customers)'
DEBUG: Assigned hint 'NestLoop(c o)' to Query at location 15
```

通过这些日志，您可以清楚地看到：
- 每个Query在源文本中的位置
- 每个提示的位置和内容
- 提示是如何被匹配到Query的
- 为什么某个提示没有被匹配（距离太远、已被消费等）

## 技术细节

### PostgreSQL解析器集成

我们的实现充分利用了PostgreSQL解析器提供的准确信息：

1. **`stmt_location`字段**：PostgreSQL解析器为每个Query结构准确记录了其在源SQL中的起始位置
2. **位置精确性**：这个位置指向SELECT关键字的开始
3. **子查询支持**：所有类型的子查询（SubLink、RTE subquery、CTE）都有准确的位置信息

### 匹配算法对比

**原算法：**
```c
// 找到第一个在Query位置前100字符内的提示
if (pos->hint_end <= stmt_location &&
    stmt_location - pos->hint_end < 100)
    return pos->hint_text;  // 立即返回
```

**新算法：**
```c
// 遍历所有提示，找到最接近的未消费提示
foreach(lc, hint_positions)
{
    if (pos->consumed) continue;  // 跳过已消费

    if (pos->hint_end <= stmt_location)
    {
        int distance = stmt_location - pos->hint_end;
        if (distance < 200 && distance < best_distance)
        {
            best_match = pos;       // 记录最佳匹配
            best_distance = distance;
        }
    }
}

if (best_match)
{
    best_match->consumed = true;  // 标记为已消费
    return best_match->hint_text;
}
```
